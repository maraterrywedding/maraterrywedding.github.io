## What was built

### Project foundation
Astro 5, static output, no UI framework. Three languages come from **one** set
of page files: `src/pages/[...locale]/` with a rest parameter that matches the
empty segment for English, so `/`, `/de/` and `/pt/` are generated from a single
source file each. No triplicated markup, so the languages cannot drift apart.

### Single source of truth
`src/data/event.ts` holds the date, ceremony time, venue, coordinates, RSVP
deadlines and album links. Nothing else in the project hardcodes any of them.
The ceremony time carries a `ceremonyTimeConfirmed: false` flag, and the home
page renders a "still to be confirmed" pill off the back of it — flip the flag
and the pill disappears.

### i18n
- `src/i18n/{en,de,pt}.json`, flat dotted keys, all three complete for the shell.
- `t()` falls back to English, and **throws in dev** if an English key is
  missing, since that is always a bug.
- `pending-translation.json` is the mechanism that stops a translation going
  missing quietly: a key may only be absent from German or Portuguese if it is
  listed there, and the test suite enforces it. Block 6's job is to empty it.
- Placeholders are checked across locales — a German string that drops `{date}`
  would otherwise print a literal `{date}` to a guest.

### Path handling
`src/lib/paths.ts` builds every internal link. It handles the GitHub Pages
sub-path case and, critically, `switchLocalePath` preserves the **query string
and hash**. Switching language on `/rsvp/edit?t=<token>` must not drop the
token, or a guest loses the only credential they have for their own RSVP.
That case has its own test.

### Design
Hand-written CSS custom properties in `src/styles/tokens.css`. Light purple and
darker green on warm paper. The governing contrast rule is written into the
file: lilac is fills and decoration, forest and ink carry anything you read.
Lilac-700 is the one purple safe for text.

### Photos
`scripts/prep-photos.mjs` turned 29 MB of phone originals into 5.1 MB of web
sources, which Astro then serves as responsive WebP. It **strips EXIF**, which
matters — the originals carried GPS coordinates, and publishing the couple's
home location on a public site would have been a real leak.

`src/data/photos.ts` references images by meaning (`hero`, `venueFromRiver`)
rather than filename, with trilingual alt text living next to each image.

## Bugs found and fixed during visual review

Worth recording, because three of them only appear in a browser:

1. **Hero text overlapped the couple's faces on mobile.** The image was a fixed
   4:3 ratio, too short for the copy, which spilled upward over the photo.
   Rebuilt as a single-cell grid with a `min-height`, so the hero is always at
   least as tall as its text.
2. **The desktop navigation was invisible.** It was a `<details>` disclosure, and
   CSS cannot force a closed `<details>` open — so at desktop width the nav
   simply wasn't there. Replaced with a real `<button aria-expanded>` plus ~20
   lines of JS, with a `<noscript>` fallback that leaves the menu open.
3. **The hero rendered 960px tall instead of 640px.** Two causes, in sequence:
   `Photo.astro` declared `height: auto` at a specificity that beat the hero's
   `height: 100%`; and once that was fixed, the image was still sizing the grid
   row it was trying to fill — a circular dependency the browser resolves by
   falling back to intrinsic height. Fixed by taking the image out of flow.
4. **Copy bugs**: "Thursday Thu 10 June", and the date printed twice in one block.
5. My own screenshot script was capturing mid-scroll, because global
   `scroll-behavior: smooth` was still animating. Now scrolls with
   `behavior: 'instant'`.
